# Кодомандри — приборкай багів

Пригодницька гра-тренажер для шляху full-stack розробника. Кожна технологія — окремий світ (як виміри в Minecraft): світ-хаб із порталами веде на намальовані карти світів, де з кожною пройденою місією відкриваються нові землі.

**Стек:** чистий HTML/CSS/JS, без фреймворків, бібліотек і збірки. Відкрий `index.html` у браузері (працює і через `file://`) або опублікуй репозиторій через GitHub Pages.

## Світи

| Світ | Технологія | Стан |
|---|---|---|
| Зелене королівство | JavaScript — 96 рівнів за планом «96 рівнів із ментором», 11 локацій; наскрізний проєкт — навчальний трекер | ✅ готовий |
| Острів будівельників | HTML і CSS — 53 рівні, 12 локацій (семантика → сучасний CSS → готель «Люм'єр») | ✅ готовий |
| Дерево часу, Глибини, Кришталеві гори, Арена випробувань, Механічне місто, Шахти даних, Пекельні кузні, Небесна фортеця | Git, JS поглиблено, TypeScript, тестування, React, SQL, Node.js, безпека й деплой | 🏗 будуються |

## Як грати

- **Світи** — зала порталів «Обери свій світ»: 11 арок на терасах, клік вибирає світ, праворуч — його опис, прогрес, наступний крок і кнопка «Продовжити пригоду». Повторний клік по відчиненому порталу веде на карту світу.
- **Екран локації** — велика ілюстрація локації: місії лежать на кам'яних дисках стежки (пройдені, «Ти тут», закриті), трофей у кінці шляху, живі світлячки й кнопка «Увійти». Відкривається кліком по локації на карті.
- **Карта** — намальована карта світу з підписами локацій і туманом над закритими землями. Клік по локації відкриває її екран.
- **Місія** — панорама з героєм і XP під заголовком; нижче умова й навчальні секції ліворуч, редактор, консоль і результат праворуч. `Ctrl+Enter` запускає перевірку. У світі HTML/CSS є вкладки `index.html` / `style.css` і **Перегляд** — жива сторінка.
- **Зосередження й телефон** — кнопка «Зосередитись» у місії ховає сцену й декоративні малюнки (код, курсор і результат лишаються). На телефоні місія поділена на вкладки «Завдання / Код / Результат», а «Запустити» завжди видно над меню й клавіатурою.
- **Перевірка розуміння** (світ JS) — під чеклистом місії три окремі статуси: автотести місії, **зміна умови** (невелика зміна завдання, перевіряється автоматично й відкривається після автотестів) і **пояснення** — коротке запитання, яке перевіряє ментор (автоматично не оцінюється). Пройдені зміни умови зберігаються в `progress.variations`.
- **Довідник** — сторінка кожної пройденої місії: теорія, приклад, твоє рішення, еталон і підказка; пошук і фільтри. Відкривається і як бічна панель просто на екрані місії.
- Помилки не караються: наставник підказує, а після трьох спроб пропонує подивитися рішення.
- Прогрес кожного світу, XP, серія з першої спроби, трофеї й чернетки зберігаються в `localStorage` (`js-game-progress`, `js-game-progress:web`, `js-game-drafts…`). Рівень героя рахується з досвіду всіх світів. Якщо зміст світу перебудовано, у `WORLD_DATA.<світ>.contentVersion` піднімають версію — і старий прогрес цього світу скидається.
- Резервна копія з версією формату містить прогрес, XP, статуси змін умов, позначки повторення, етап продовження та чернетки. Перед відновленням файл проходить повну перевірку й показує підсумок; некоректний файл не змінює сховище. Завантаження й відновлення доступні в профілі героя.
- Продовження відкриває останню незавершену місію або незавершену зміну умови; відповіді й кодові чернетки зберігаються окремо від статусу проходження. Теми можна позначити для повторення на екрані місії й відкрити з профілю без скидання прогресу.
- Підказка відкривається трьома кроками: навідне запитання, пояснення з навчального матеріалу, короткий фрагмент прикладу. Невдалі перевірки показують конкретний випадок та очікуване/фактичне значення, коли це не розкриває відповідь multiple-choice.

## Структура

```
index.html            — хаб, карта світу, проєкти, довідник, профіль (#hub, #map, …)
levels/level.html     — екран місії (?world=js|web&id=N)
css/style.css         — усі стилі (токени кольорів у :root)
js/worlds.js          — реєстр світів і порталів
js/levels.js          — світ JavaScript: 96 рівнів + 11 локацій (завдання, критерії «Зараховано», тести; вхідні дані тестів через testCases[].inputs)
js/levels-checks.js   — перевірка розуміння для 96 JS-місій: запитання для ментора й зміна умови з власними тестами
js/levels-web.js      — світ HTML і CSS: 53 рівні + 12 локацій
js/storage.js         — localStorage (окремий прогрес для кожного світу)
js/game.js            — розблокування, XP, рівень героя, трофеї, стани порталів
js/art.js             — процедурний піксель-арт і JS-світ (орієнтири, біоми, рельєф)
js/art-web.js         — арт острова будівельників
js/locations-art.js   — екрани локацій: ілюстрації та координати дисків місій
js/scene.js           — ілюстрована сцена локації з Мандрівником (екран місії й картка місії на карті)
js/ui.js              — іконки, меню, підсвітка JS/HTML/CSS, налаштування анімації
js/handbook.js        — довідник героя
js/checker.js         — пісочниці й перевірка відповідей усіх типів завдань
js/app.js, mission.js — логіка екранів
tests/run.html        — автоперевірка: еталонні рішення всіх рівнів проходять, стартовий код — ні; еталон зміни умови проходить її тести, а еталон рівня — ні
tests/unit.html       — модульні тести рушія: цикли без дужок не вішають сторінку, порівняння масивів, гра без localStorage, одноразова міграція чернеток
tests/learning-data.html — ізольовані перевірки експорту/відновлення, сумісності збережень, етапів, чернеток і повторення
tests/ui-disclosure.html — ізольована перевірка відновлення закритого блока зміни умови
tests/mutants.html    — мутаційна перевірка: «правдоподібно неправильні» варіанти еталонів (межі, trim, preventDefault, забутий return…) мають не пройти тести
assets/sandbox/       — картинки для завдань із версткою
assets/locations/     — ілюстрації локацій (js-1…11.webp, web-1…12.webp)
assets/fonts/         — локальний Roboto Slab 800 для wordmark; Apache 2.0, джерело й ліцензія в каталозі
assets/maps/          — зала порталів (hub.webp) і намальовані карти світів (js-map.webp, web-map.webp)
assets/art/           — ілюстрація героя для бокового меню
docs/integration.md   — як модулі додають дії в інтерфейс (повторення, підказки, резервна копія, продовження)
assets/trophies/      — намальовані трофеї локацій (<icon>.webp, список — window.TROPHY_ART)
```

## Як перевіряються відповіді

| Тип | Перевірка |
|---|---|
| `predict-output` | кожен рядок порівнюється окремо (без урахування пробілів, лапок навколо, регістру й одиниці виміру) |
| `multiple-choice` | обраний варіант = `expectedAnswer` |
| `fill-blank` | вміст пропуску без пробілів = одному з допустимих варіантів |
| `write-function`, `fix-code` | JS виконується через `new Function` у пісочниці: `try/catch`, захист від безкінечних циклів, підставні `document` / `localStorage` / `fetch` / таймери |
| `write-markup`, `fix-markup` | сторінка рендериться в ізольованому `iframe` без скриптів; тести читають DOM, обчислені стилі, розміри й медіазапити на різній ширині; лінтер попереджає про незакриті теги |

## Оновлення сайту

GitHub Pages дозволяє браузеру кешувати кожен файл до 10 хвилин окремо. Щоб після оновлення браузер не змішав старі й нові скрипти, усі скрипти й стилі в `index.html` і `levels/level.html` підключаються з номером версії (`?v=20261027w`). **Після кожної зміни JS чи CSS заміни цей номер в обох файлах.** Якщо сторінка все ж не збереться, гравець побачить пояснення й кнопку «Оновити сторінку» замість порожнього екрана.

## Як додати світ

1. Додай запис у `js/worlds.js` зі `status: "open"`.
2. Створи `js/levels-<id>.js`, що реєструє `WORLD_DATA[id] = { locations, levels, projects }`.
3. Створи `js/art-<id>.js` з `Art.registerWorld(id, { points, landmarks, biomes })` і трофеями `Art.addItems(...)`.
4. Підключи обидва файли в `index.html`, `levels/level.html` і `tests/run.html`, відкрий `tests/run.html`.
