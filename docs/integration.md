# Інтеграція модулів у інтерфейс «Кодомандрів»

Інтерфейс уже має місця для дій, які додають окремі модулі: продовження навчання,
резервна копія, підказка й позначення теми для повторення. Модуль **не створює власних
кнопок у розмітці**. Він реєструє дію, а інтерфейс показує її в потрібному місці
в єдиному стилі. Порожнє місце невидиме, тож поки модуля немає, гравець нічого
недоробленого не бачить.

## Як підключити модуль

1. Поклади файл у `js/`, наприклад `js/review.js`.
2. Підключи його **після** `ui.js` в `index.html` і `levels/level.html`
   (з тим самим `?v=…`, що й решта файлів; після змін JS чи CSS цей номер піднімають в обох файлах).
3. Зареєструй дію:

```js
GameUI.addAction("review", {
  id: "review-toggle",
  label: (ctx) => (isMarked(ctx.world, Number(ctx.level)) ? "У повторенні" : "Повторити тему"),
  icon: "flag",                              // назва з UI.icon: flag, bulb, book, copy, reset, check…
  title: "Додати тему цієї місії до повторення",
  pressed: (ctx) => isMarked(ctx.world, Number(ctx.level)),   // для перемикачів → aria-pressed
  onClick(ctx, button) {
    toggleMark(ctx.world, Number(ctx.level));
    GameUI.refresh("review");                // перемалювати кнопку з новим станом
    UI.toast(UI.icon("flag") + " <span>Тему додано до повторення</span>");
  },
});
```

| Метод | Що робить |
|---|---|
| `GameUI.addAction(slot, action)` | додає або замінює (за `id`) дію в усіх місцях `slot`, зокрема в тих, що з'являться пізніше |
| `GameUI.removeAction(slot, id)` | прибирає дію |
| `GameUI.refresh(slot?)` | перемальовує кнопки (після зміни стану) |

Поля дії: `id`, `label` (рядок або `ctx => рядок`), `onClick(ctx, button)`; необов'язкові —
`icon`, `title`, `variant` (`"ghost"` за замовчуванням, `"primary"` — лише для головної дії),
`isVisible(ctx)` (сховати дію в конкретному місці), `pressed(ctx)` (стан перемикача).

`ctx` — дані місця: `world` (`"js"` / `"web"`), `level` (id місії **рядком**, перетвори через `Number`)
і `place`. Значення в таблиці нижче.

## Місця для дій

| Місце | Де на екрані | `ctx` | Для чого |
|---|---|---|---|
| `review` | місія → заголовок, поруч із «Зосередитись» і «Довідник» | `world`, `level` | позначити тему для повторення (перемикач) |
| `hint` | місія → «Підказка», після тексту підказки, перед кнопкою «Показати рішення» | `world`, `level` | додаткові або поступові підказки |
| `backup` | профіль → розділ «Збереження прогресу» (розділ з'являється лише разом із дією) | `place: "profile"` | експорт / імпорт резервної копії |
| `continue` | хаб → під «Продовжити пригоду»; карта → під «Почати місію» | `world`, `level`, `place: "hub"` / `"map"` | другорядні дії навчання, наприклад «Повторити теми (3)» |

### Чого не дублювати

- **Продовження навчання.** Головні кнопки вже є: «Продовжити пригоду» в хабі, «Почати місію»
  на карті, «Наступна місія» після проходження. Вони позначені `data-action="continue"`
  (у хабі й на карті ще й `data-world`, `data-level`). Щоб змінити, куди вони ведуть,
  зміни ціль (`Game.currentLevelId` чи `href` цих кнопок), а не додавай нову головну кнопку.
  У місце `continue` — лише другорядні дії.
- **Підказка.** Розкривний блок «Підказка» з текстом `level.hint` уже є, а після трьох
  невдалих спроб у ньому з'являється «Показати рішення» (`offerSolution` у `js/mission.js`).
  Нові підказки додавай у місце `hint`, а не окремою кнопкою деінде.
- **Перевірка розуміння.** Три статуси («Автотести місії», «Зміна умови», «Пояснення з ментором»)
  малює `syncUnderstanding()` у `js/mission.js` з `progress.completed` і `progress.variations`.
  Якщо зміниться спосіб зберігання цих даних, онови лише цю функцію; розмітку статусів не чіпай.

## Що вже є в інтерфейсі й що варто знати модулям

- **Режим зосередження** (кнопка «Зосередитись» у місії) лише ховає декоративні частини класом
  `.mission.is-focus`. Вибір зберігається в `localStorage` під ключем `js-game-focus`.
  Це налаштування вигляду, а не прогрес: резервна копія може його не включати.
- **Телефон (≤ 760 px).** Місія поділена на вкладки «Завдання / Код / Результат»
  (`.mission[data-pane]`). Після «Запустити» автоматично відкривається «Результат»,
  а курсор у коді зберігається. Дії в місцях `review` і `hint` видно у вкладці «Завдання» або
  в заголовку. Повідомлення для гравця краще показувати через `UI.toast(...)`, бо його видно в будь-якій вкладці.
- **Доступність.** Кожна дія — справжня `<button>` з текстом. Якщо `label` короткий, пояснення
  дай у `title`. Не покладайся лише на колір: стан перемикача передає `pressed`.
- **Схема збереження** (`js/storage.js`) і перевірка відповідей (`js/checker.js`) інтерфейсом
  не змінювались.
