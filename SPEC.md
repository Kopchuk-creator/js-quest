# Специфікація проєкту: «JS Quest — приборкай багів»

Пригодницька RPG-гра для вивчення JavaScript. Гравець відновлює фентезійний світ, проходячи теми JS — кожна пройдена тема фізично змінює світ на карті (відчиняється брама, відбудовується міст, переможений бос-баг).

## Контекст для Claude Code

Будуємо навчальну гру-сайт для вивчення JavaScript. Автор — фронтенд-розробник, працює **тільки на vanilla HTML/CSS/JS, без фреймворків і білд-інструментів**, хостить готові сайти на GitHub Pages. Тримайся цього стеку: ніякого React/Vue/webpack/npm build step. Один репозиторій, статичні файли, відкривається просто через відкриття `index.html` або GitHub Pages.

Інтерфейс — українською мовою.

## Ціль продукту

96 рівнів, об'єднаних у 14 "арок" (глав). Кожен рівень — одна маленька концепція JS (5-15 хв роботи). Проходження рівня = розв'язання одного практичного завдання прямо в браузері, з миттєвою перевіркою правильності. Прогрес зберігається локально (`localStorage`), щоб користувач міг повертатись і продовжувати з того ж місця.

## Дизайн і візуальна концепція

**Референс-макети додані поряд із цим файлом:** `mockups/mockup-map-screen.png` (головний екран карти) і `mockups/mockup-mission-screen.png` (екран проходження місії). Орієнтуйся на них як на основне джерело істини для вигляду, кольорів і компонування — текст нижче лише уточнює деталі.

**Стиль:** пікселарт для персонажа, світу й сцен — текст, кнопки, UI-елементи сучасні й легко читабельні (без піксельного шрифту). Темний графітовий фон, жовті акцентні кнопки (колір JavaScript), м'ятно-зелені позначки виконаних завдань/станів успіху.

### Екран 1 — Карта світу (головна сторінка)
- Велика ілюстрована карта зліва/по центру: стежки, ліси, печери, замок, острови — локації з'єднані пунктирним шляхом.
- Піксельний герой-аватар стоїть на поточній (активній) локації.
- Кожна локація на карті: пройдена (зелена галочка), поточна (підсвічена, "Ти тут"), заблокована (замок-іконка, затемнена) — розблоковується послідовно.
- Права панель: картка поточної місії — назва, коротка історія/опис, сцена-ілюстрація, час проходження, нагорода (XP), кнопка "Почати місію" (велика, жовта).
- Верхня права панель: рівень героя і шкала досвіду (X / Y XP).
- Нижня панель: "Інвентар героя" — колекція трофеїв/предметів, здобутих за проходження арок (символічна нагорода, не впливає на механіку).
- Ліве бокове меню: Карта, Практика, Проєкти, Трофеї.

### Екран 2 — Проходження місії (рівня)
Триколонкова структура:
- **Зліва:** історія/легенда місії (короткий ігровий текст, що подає тему як квест), чеклист критеріїв виконання завдання, кнопка "Підказка" (розкривається за бажанням, без штрафів).
- **По центру:** редактор коду (вкладка з іменем файлу на кшталт `getKey.js`), кнопки "Запустити" і "Скинути", під редактором — консоль з результатом виконання (✓/✗ по кожному тест-кейсу).
- **Справа:** сцена, що реагує на результат — у неактивному стані показує "загадку" локації (наприклад, зачинена брама), після успішного проходження програє стан "вирішено" (брама відчинена) і показує банер "+XP" та кнопку "Наступна місія".
- Зверху — хлібні крихти (Локація → Назва місії) і прогрес-бар місій усередині поточної локації (кружечки, крок 1 з 5 тощо).

**Обробка помилок:** без втрати життів/спроб. Неправильний результат показує дружню підказку у форматі історії (інакше кажучи, "наставник" у вигляді персонажа-помічника підказує), і гравець просто пробує ще раз.

## Технічна архітектура

1. **Структура даних рівнів** — один JSON/JS-файл `levels.js` з масивом об'єктів такого вигляду:

```js
{
  id: 1,
  arc: "Змінні, типи, оператори",       // внутрішня назва (контент/логіка)
  arcNumber: 1,
  locationName: "Табір змінних",         // показується гравцю на карті (див. таблицю локацій вище)
  title: "let vs const",
  concept: "Коротке пояснення теми (2-4 речення), з прикладом коду",
  missionStory: "1-2 речення ігрової легенди місії (для лівої колонки екрана проходження)",
  worldEvent: "Що відбувається у світі після проходження (для правої сцени-реакції)",
  taskType: "predict-output" | "fix-code" | "write-function" | "multiple-choice" | "fill-blank",
  prompt: "Текст завдання для користувача",
  starterCode: "Код, який користувач бачить і редагує (або null для predict-output/multiple-choice)",
  testCases: [ { input: [...], expectedOutput: ... } ], // для write-function
  expectedAnswer: "...", // для predict-output / fill-blank / multiple-choice
  options: ["...", "..."], // тільки для multiple-choice
  hint: "Підказка, яку можна відкрити за бажанням",
  difficulty: 1 // 1-3
}
```

2. **Типи завдань і як їх перевіряти:**
   - `predict-output` — показати код, користувач вводить що виведе `console.log`. Порівняти рядок з `expectedAnswer` (з trim/normalize).
   - `multiple-choice` — питання + варіанти, звірити вибір з `expectedAnswer`.
   - `fill-blank` — код з пропуском (`___`), користувач вписує частину коду. Перевірка через regex або точне співпадіння очищеного рядка.
   - `write-function` — користувач пише тіло функції в `<textarea>`/простому code-editor; виконати через `new Function(...)` в ізольованому контексті, прогнати `testCases`, звірити результат. **Загортати виконання в try/catch**, щоб помилка користувача не ламала сторінку.
   - `fix-code` — показати код з багом (використовуй реальні пастки з Арки VI нижче), користувач редагує, перевірка як у `write-function`.

3. **UI/UX:**
   - Головна сторінка — мапа/список арок, кожна арка розгортається в список рівнів.
   - Рівень: заблокований (сірий, недоступний) / доступний (можна почати) / пройдений (галочка). Розблоковується послідовно — рівень N+1 відкривається тільки після проходження N.
   - Прогрес зберігається в `localStorage` під ключем на кшталт `js-game-progress` (масив пройдених id).
   - Проста ігрова механіка: лічильник пройдених рівнів, можливо "streak" (скільки поспіль без помилок), легка анімація на завершення рівня.
   - Адаптивність під мобільні екрани (однокнопкова взаємодія там, де можливо).

4. **Структура файлів** (за зразком існуючих проєктів автора — `index.html` + `script.js` на кожну одиницю контенту):
```
/
  index.html          — Екран 1: карта світу
  /css/style.css
  /js/
    app.js            — логіка гри, рендер, перевірка відповідей
    levels.js         — масив усіх 96 рівнів (дані, опис нижче)
    storage.js        — робота з localStorage
  /levels/
    level.html         — Екран 2: проходження одного рівня (?id=N у query)
  /assets/
    /mockups/          — референс-макети дизайну (додані поряд із цим файлом)
    /art/               — піксель-арт героя, локацій, сцен (генерується/додається окремо)
```

5. **Важливо:** контент (пояснення, формулювання завдань, тестові кейси) генеруй сам на основі таблиці нижче — там дано тему і тип завдання для кожного рівня, цього достатньо, щоб написати коректне й технічно правильне завдання. Не вигадуй синтаксис JS, якого немає — звіряйся зі стандартом ES6+.
